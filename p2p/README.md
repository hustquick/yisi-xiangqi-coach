# 中国象棋网络对战（联调版）

当前接入 `windowsHTML` 和 `html` 两个网页客户端。安卓 / iOS 原生客户端尚未接入，不能把旧 APK 当作网络对战版。

所有账号与好友操作都在“网络对战”模块内完成。登录只输入一次密码；切换注册后显示确认密码，两次不一致不提交。上线后可按完整账号（不区分大小写）搜索、添加或移除好友；好友列表持久化到账号数据库。在线、离线和对局中状态随在线连接推送更新，离线或忙碌好友不能被邀请。添加是单方收藏，不自动把对方加入你的好友关系，也不表示双方已相互同意好友申请。

模块内直接显示账号和账户状态下拉框（在线 / 隐身 / 退出），只保留一个“好友列表”展开入口，不显示重复的账户信息、恢复在线或退出登录按钮。状态选择保存到服务器；隐身账号在好友列表与搜索结果中均显示离线，不公开是否隐身或忙碌。隐身玩家仍能主动邀请在线玩家（发起邀请即向对手暴露账号）；已有对局不受状态切换影响。好友列表支持查看好友账号、当前公开状态和邀请可用性。对局中需先退出对局，才能退出账号。

账号使用服务端 SQLite 保存，密码使用独立随机盐的 scrypt 哈希；密码只要求非空、最多 128 个字符，无复杂度要求，允许一个字符的短密码（更容易被猜中，不要复用重要账号密码）。登录令牌仅在客户端内存保存，12 小时有效。当前需要该账号服务在线，不是完全去中心化账号。服务器只传递在线状态、邀请和连接信令，不接收走棋或棋谱。

邀请方执红，接受方执黑，从标准初始局面开始。走棋使用有序 WebRTC DataChannel，携带对局 ID、半回合序号和落子前局面；双方独立检验规则和回合，收到非法消息或确认超时即锁定对局。禁止联网时单方悔棋、重开、摆盘和载入。断线重连会核对双方现有局面，局面不一致不自动覆盖对手棋盘；关闭或刷新网页后的棋局恢复尚未实现。退出不是竞技认输结算，没有排名或防引擎作弊保证。

## 服务运行

需要 Node 22.13+（SQLite 内置支持）：

```sh
cd p2p
npm install
npm test
P2P_ORIGINS=http://localhost:8080 npm start
```

网页构建前先在 `p2p` 和对应客户端目录运行 `npm install`。`windowsHTML` 执行 `npm run build`；联网时以 HTTP 本机服务或 HTTPS 托管网页，不能只双击文件保证联网功能。

## 已部署到 Oracle 主机

- SSH 别名 `tokyo`，公网 IP `132.226.5.8`。
- `yisi-xiangqi-signaling`：仅监听 `127.0.0.1:8790`，不对公网暴露明文登录。
- `yisi-xiangqi-turn`：UDP / TCP `3478`，UDP 中继端口 `49160–49200`。
- 项目路径 `/home/ubuntu/projects/yisi-xiangqi-p2p`。独立 Node 运行时，不替换系统 Node，不改量化程序。
- 中继使用一小时临时凭证，密钥只在主机配置中；每凭证最多 4 分配、全局最多 40 分配，单分配 64 KiB/s，上限不是总流量预算。
- 本机防火墙已放行中继端口并持久化；从外部探测 TCP 3478 仍超时，Oracle 安全列表 / NSG 尚需确认放行。

没有域名时可先安全联调：

```sh
ssh -N -L 8790:127.0.0.1:8790 tokyo
```

网页在 `http://localhost:8080` 打开，应用自动使用本机隧道，不需要用户输入服务器。正式部署默认使用网页同源服务；独立服务地址由部署人员通过 HTML 的 `meta[name="yisi-network-endpoint"]` 配置，玩家界面不显示地址或网络配置。这只是本机 SSH 隧道联调，不代表两台手机公网部署完成。正式上线需要域名、HTTPS 反向代理、对应允许来源；未提供自签名证书或引导用户绕过证书校验。

## Oracle 控制台待操作

在该实例使用的安全列表或 NSG 中，允许来源 `0.0.0.0/0` 到：TCP 3478、UDP 3478、UDP 49160–49200。不要开放 8790 或删除现有规则。有域名和 HTTPS 配置后才另行放行 TCP 443（证书签发可能需 TCP 80）。云防火墙修改须在账号控制台完成；本次没有 Oracle API 凭据。

部署配置参考 [coturn 官方配置说明](https://github.com/coturn/coturn/blob/master/examples/etc/turnserver.conf)。Ubuntu 提供的 coturn 包仍需在正式公网验收前核对安全更新；公网 TURN 强制中继测试尚未通过。

## 验证范围

`npm test` 检查注册、密码校验、来源限制、令牌替换和未授权对局操作。`npm run test:browser` 使用两个独立浏览器上下文连接真实云端服务，经真实 WebRTC 完成邀请、双方落子、禁止单方重开、重连和退出；需先开启 SSH 隧道和网页本机服务，`CHROME_PATH` 可指定 Chrome 路径。

尚需跨网络真机、强制 TURN、移动端后台恢复、长期流量和异常消息压力测试。此版本是可联调实现，不声称公网正式交付。
